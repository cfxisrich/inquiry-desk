# 询报价工作台

面向设备配件商的本地试点应用，把询盘录入、需求确认、商品匹配、报价版本和跟进记录放在同一个工作台。

React + TypeScript + Vite / Node.js + Express / SQLite。单工作区，支持管理员和普通用户账号，默认仅监听本机，不包含支付、自动发邮件或后台通知。所有用户共享商品、询盘、报价和跟进记录。

## 启动

需要 Node.js 24 或更新版本，以及 pnpm 11 或更新版本。请在项目根目录运行：

```sh
pnpm install
pnpm dev
```

打开 <http://127.0.0.1:5173>。开发前端端口为 5173，API 为 4311；开发代理固定指向 4311。

首次打开页面时，先设置管理员的用户名、姓名和密码，创建后自动登录。没有默认账号或密码，也没有公开注册入口。

首次启动业务数据库为空。登录后可以录入自己的资料，也可以在空工作台点击载入演示数据。演示数据是虚构的，只会在明确点击后写入；非空数据库不会混入演示资料。

构建并运行完整应用：

```sh
pnpm build
pnpm start
```

打开 <http://127.0.0.1:4311>。`pnpm start` 同时提供构建后的前端和 API。数据库默认保存在 `data/inquiry.sqlite`，关闭或重启不会清空。

## 登录与用户管理

- 用户名为 3–40 位字母、数字、下划线、点或短横线，忽略大小写；密码为 8–128 位。
- 首位管理员通过首次设置页面创建。管理员在「用户管理」中创建普通用户或其他管理员、启用或停用账号、重置其他用户密码。
- 普通用户可使用全部业务功能，但不能管理用户。管理员不能停用自己；修改自己的密码需在「我的账号」中提供当前密码。
- 点击右上角账号入口可以修改密码或退出登录。修改密码会退出该用户的全部登录会话，需要重新登录。
- 管理员停用账号或重置密码同样会使该用户全部会话失效；重新启用后旧会话仍然不可用。
- 登录会话保存在 SQLite，通过 HttpOnly、SameSite=Strict Cookie 识别，有效期为 7 天；退出登录会立即撤销当前会话。密码仅保存随机盐 scrypt 哈希。
- 同一来源地址在 15 分钟内登录失败 10 次后，暂时限制继续登录。
- 升级已有数据库只新增用户与会话表，不改写现有商品、询盘或报价。首次创建管理员后，原有数据仍由同一工作区共享。

## 跑通第一笔报价

1. 在商品目录导入 `samples/products.csv`，或手动添加商品。
2. 新建询盘，填入客户与联系方式，粘贴 `samples/inquiry.txt` 中的示例文本。
3. 手工补充需求行，或配置模型后使用 AI 提取。确认型号、规格、数量及商品候选。
4. 确认商品、单价、运费、含税标记和有效期，保存报价。
5. 在报价页面打印，或通过浏览器打印对话框保存为 PDF。向客户发送后，手动标记已发送。
6. 记录沟通结果和下次跟进日期。成交或丢单后，询盘不再出现在待跟进任务中。

报价采用人民币，金额精确到分，数量为正整数。含税/未税标记用于说明价格口径，应用不额外计算税额。运费单列。

保存报价会固化当时的商品名称、规格、价格及客户信息。更新商品目录或询盘客户信息不会改变旧报价；重新报价产生新版本。生成报价不代表已经发送，标记发送也不会实际发送邮件。

在报价详情点击「复制此版报价」，可基于当前查看的任意历史版本重新报价。商品行、数量、议价单价、公司名称、含税口径、运费和说明会保留；有效期重新设为当天起 14 天，可手动调整。弹窗显示议价单价与当前目录参考价的差异，保存时使用当前询盘客户资料和商品目录资料，产生新的未发送版本，原报价不变。

## 询盘编辑与 AI 结果确认

- AI 提取先保存当前询盘，再打开结果预览。勾选需要的采购需求和待确认信息后，点击「追加到现有需求」；已有需求、商品匹配和客户资料保持不变。取消预览不会采纳模型结果。
- 采纳结果后仍需保存询盘。待确认信息会随询盘保存，再次打开仍可查看；确认清楚后可逐项标记已解决，再保存。每条询盘最多 100 项需求、30 项待确认信息。
- 询盘或跟进内容未保存时，站内切换页面会询问是否放弃；刷新、关闭页面由浏览器显示离开提醒。选择留下会保留页面内的编辑内容，选择放弃不会自动保存草稿。
- 每条询盘带有独立的 `revision`。旧页面提交会返回 409，保留本地编辑内容；可以「查看服务器版本」对照，或明确选择「放弃本地修改，载入最新版本」后重新编辑。系统不会自动合并或覆盖他人的修改。
- 已有数据库在启动时为缺字段的询盘补齐 `revision: 1` 和 `missingFields: []`，其他数据保持原样。报价、发送标记和跟进引起的询盘变更同样更新版本号。

API：`GET /api/inquiries/:id` 获取询盘及版本；更新询盘、修改状态和新增跟进均须提交当前 `revision`，缺少版本返回 400，版本过期返回 409。`missingFields` 是随询盘保存的待确认信息数组。

## 商品 CSV

使用 UTF-8 编码，表头为：

```csv
sku,name,specification,unit,price
BR-6204,深沟球轴承,6204-2RS / 20×47×14 mm,件,19.90
```

`price` 的单位为元，允许非负数及最多两位小数。SKU、名称和单位必填；规格可以为空。包含逗号的字段应使用双引号包围。支持 UTF-8 BOM。

一次最多导入 5,000 条。上传后先显示预览，区分新增商品、更新价格、价格未变和错误行，并展示原参考价与新参考价。预览不会写入商品目录。

确认导入时，新 SKU 新增商品；已有 SKU 仅更新参考价格，名称、规格、单位、商品 ID 和创建时间保持不变，历史报价也不会改变。SKU 按完整文本区分大小写。文件内重复 SKU 或无效字段会显示对应行号；存在错误时不能确认，整批均不会写入。预览后若涉及的商品发生变化，确认会被拒绝，需要重新预览后提交。

API：`POST /api/products/import/preview` 接收 `{csv}` 并返回预览与 `fingerprint`；`POST /api/products/import` 接收 `{csv, fingerprint}` 确认新增及调价。不提供 `fingerprint` 时保留仅新增模式，遇到已有 SKU 会整批拒绝。

## AI 提取配置

复制 `.env.example` 为 `.env`，在服务端填写配置，然后重启服务：

```dotenv
COMPANY_NAME=你的公司名称
PORT=4311
DATABASE_PATH=./data/inquiry.sqlite
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=填写你自己的服务端密钥
AI_MODEL=填写服务商提供且支持JSON模式的模型名称
```

支持提供 Chat Completions `/chat/completions` 接口与 JSON mode 的模型服务，`AI_BASE_URL` 填接口基础地址，不包含 `/chat/completions`。没有预设模型，也没有内置密钥。

未配置模型时可以正常使用手工录入、商品目录、报价和跟进。只有用户点击 AI 提取时，已保存的原始询盘才会发送给配置的模型服务。模型结果需人工确认；缺失信息保持待补充，不自动编造价格或替用户确认商品。

密钥只在服务端读取，API 状态接口不会返回密钥。`.env` 已加入忽略列表。运行环境没有模型密钥时，不能据此声称真实模型提取已通过验证。

接口格式参考：[OpenAI Chat Completions API](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。其他服务商是否支持同样的 JSON 参数，以其实际接口为准。

## 数据备份与运行范围

备份前停止应用，复制完整的 `data/` 目录。若设置了 `DATABASE_PATH`，备份对应数据库及同目录下与它同名的 `-wal`、`-shm` 文件（如果存在）。恢复时也先停止应用。

本版包含账号登录和管理员权限，业务数据仍属于一个共享工作区，不按用户隔离。服务仍默认仅绑定本机 `127.0.0.1`；此次未改变部署方式。备份的数据库也包含用户和会话。
